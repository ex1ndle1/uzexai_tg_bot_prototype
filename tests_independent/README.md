# Независимые тесты UZEX

Набор написан **только по документации и метрикам**, без чтения кода решения:

- `README.md`
- `uzex_spot_data/README.md`
- `VAZIFA_UZ.md`
- фактические метрики реестра, пересчитанные напрямую из `uzex_spot_data/*.csv`

Ни один тест не импортирует `agent`, `bot` или существующий `tests/`, не
подглядывает в реализацию инструментов и не использует заранее собранную
`data/uzex.duckdb` как источник истины. Эталон считается из сырых CSV.

## Что проверяется

### `test_data_contract.py` — контракт самого реестра

Инварианты из README, не зависящие от решения:

- размеры и разбивка по годам;
- период сделок и ежедневный курс USD;
- восемь документированных состояний и их смысл:
  - `Новый` только на 30.10.2026;
  - `Исполнен` → `Поставлено = Количество`;
  - `Исполнен(Частично)` → `0 < Поставлено < Количество`;
  - даты оплаты/поставки соответствуют состоянию;
- уникальность и монотонность номеров сделок;
- ссылочная целостность: контракты, продавцы, покупатели, брокеры;
- согласованность карточки контракта и сделки;
- экспорт → USD, внутренний рынок → UZS;
- формулы из README: `объём = Количество × Лот`,
  `цена = Сумма / объём`, `сумма в сумах = сумма × курс на дату сделки`.

### `test_agent_offline.py` — чёрный ящик через CLI

Используется только документированный вход
`python -m agent.cli "<вопрос>"` в offline-режиме (без ключа LLM), поэтому
проверки детерминированы и не зависят от модели:

- сделки №… за каждый год: номер, дата, товар, сумма, статус;
- экспортная сделка отвечает в USD, внутренняя — в UZS;
- компания по ИНН: название, регион, роль;
- несуществующий ИНН и несуществующая сделка → честный отказ;
- курс USD по ISO- и «русской» дате;
- вопрос о курсе на узбекском;
- общая справка содержит 500 000 сделок и границы периода.

### `test_agent_llm.py` — опциональный end-to-end (LLM + tools)

По умолчанию **пропускается**. Включается переменной `UZEX_LLM_TESTS=1` и
требует рабочий LLM из `.env`. Проверяет русские и узбекские вопросы:

- количество сделок, суммы, пшеница, средняя цена, аннулированные, экспорт;
- сделки по контракту и по брокеру продавца;
- крупнейший продавец 2024;
- узбекские вопросы про 2024 год, пшеницу и курс;
- отказ на самолёты, несуществующий ИНН и прогноз цен на 2027.

Числа в свободном ответе сравниваются с эталоном с допуском: точные счётчики —
почти строго, денежные суммы и «трлн/млрд» — с относительной погрешностью.

## Запуск

Из корня проекта:

```bash
# быстрый детерминированный набор (без LLM)
.venv/bin/python -m unittest discover -s tests_independent -t . -v

# только данные и baseline
.venv/bin/python -m unittest tests_independent.test_data_contract \
    tests_independent.test_baseline_metrics -v

# end-to-end с моделью (медленнее, нужен рабочий LLM)
UZEX_LLM_TESTS=1 .venv/bin/python -m unittest tests_independent.test_agent_llm -v
```

`pytest` не требуется — используется стандартный `unittest`, единственная
внешняя зависимость — `duckdb`, уже указанная в `requirements.txt`.

## Известный дефект

`test_nine_digit_unknown_deal_is_not_answered_as_inn` помечен как
`expectedFailure`: offline-парсер считает девятизначный номер сделки ИНН и
отвечает «Компании с таким ИНН в реестре нет» вместо «Сделки с таким номером
нет». Тест оставлен, чтобы дефект был виден и не потерялся.

## Обновление эталона

Если реестр намеренно заменён новым:

```bash
.venv/bin/python -m tests_independent.build_baseline
```

Это перезапишет `baseline_metrics.json`. Делать так без изменения исходных CSV
не нужно — тест как раз ловит незаметный дрейф данных.
